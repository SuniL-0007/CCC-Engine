## How the Two-Layer System Works

```
Browser (client-side)                    Server (this agent)
─────────────────────                    ───────────────────
1. SheetJS parses files
2. calculateCCC() runs
3. evaluateLayer1() runs
   → up to 8 candidates
4. POST /api/recommendations ─────────→ 5. Zod validates body
                                         6. Gemini API called
                                         7. Top 5 returned
                              ←───────── 8. { recommendations }
9. ResultPanel renders
```

The browser sends the CCCResult + Layer 1 candidates.
Gemini re-ranks, enriches, and returns the final top 5.
**If Gemini fails for any reason → return Layer 1 candidates with template text. Never fail the user.**

## Step 2 — `/lib/recommendations/geminiClient.ts`

```typescript
import { GoogleGenerativeAI } from '@google/generative-ai'

const apiKey = process.env.GEMINI_API_KEY ?? ''
const modelName = process.env.GEMINI_MODEL ?? 'gemini-2.5-flash'

// Initialise once — reused across requests
const genAI = new GoogleGenerativeAI(apiKey)

export function getGeminiModel() {
  return genAI.getGenerativeModel({
    model: modelName,
    generationConfig: {
      responseMimeType: 'application/json',  // enforces JSON output
      temperature: 0.3,                       // low = consistent, structured
    },
  })
}

export const SYSTEM_PROMPT = `
You are a working capital analyst specialising in Indian textile manufacturing.
You receive a CCC (Cash Conversion Cycle) analysis for a textile business and a list
of candidate recommendations generated by a rule engine.

Your tasks:
1. Re-rank the candidates by real-world business impact, considering the company
   context (fabric types, current month/season, revenue scale).
2. Suppress any recommendation that contradicts a higher-ranked one
   (e.g. do not recommend both "extend DPO" and "pay early for discount" simultaneously).
3. Select the top 5 recommendations maximum.
4. Enrich each with:
   - A plain-language title (no finance jargon — a mill owner must understand it)
   - A 2-sentence explanation of why this matters for their specific numbers
   - Exactly 3 concrete action steps they can take this week
   - Estimated days reduction (how many CCC days this action could save)
   - Estimated cash freed in lakhs (based on the gap and revenue range provided)

Seasonal context rules:
- October, November, December = pre-Diwali/wedding season. High DIO is NORMAL.
  Do not flag DIO as critical in these months unless gap > 30 days above benchmark.
- January to March = post-season clearance. Flag slow inventory strongly.

Revenue scale context:
- under_5cr: Rs 5 lakhs gap = significant. Mention specific rupee amounts.
- 5cr_to_50cr: Rs 20 lakhs gap = significant.
- above_50cr: Rs 1 crore gap = significant.

Return ONLY valid JSON. No preamble, no markdown, no explanation outside JSON.
Schema:
{
  "recommendations": [
    {
      "id": "R1",
      "dimension": "DSO",
      "priority": "HIGH",
      "title": "plain language title",
      "explanation": "2-sentence explanation referencing their specific numbers",
      "actionSteps": ["step 1", "step 2", "step 3"],
      "estimatedDaysReduction": 12,
      "estimatedCashFreedLakhs": 8.5
    }
  ]
}
Priority must be exactly one of: "HIGH", "MEDIUM", "LOW"
dimension must be exactly one of: "DIO", "DSO", "DPO"
`
```

## Step 3 — `/app/api/recommendations/route.ts`

### 3a — Zod validation schemas

```typescript
import { z } from 'zod'

const ComponentResultSchema = z.object({
  value: z.number(),
  benchmark: z.number(),
  gapDays: z.number(),
  trendDelta: z.number(),
  dataCompleteness: z.number(),
})

const CCCResultSchema = z.object({
  dio: ComponentResultSchema,
  dso: ComponentResultSchema,
  dpo: ComponentResultSchema,
  ccc: z.number(),
  benchmarkCCC: z.number(),
  gapDays: z.number(),
  periodDays: z.number(),
  calculatedAt: z.string(), // ISO string from JSON serialisation
})

const Layer1CandidateSchema = z.object({
  id: z.string(),
  dimension: z.enum(['DIO', 'DSO', 'DPO']),
  priority: z.number(),
  title: z.string(),
  estimatedDaysReduction: z.number(),
})

const CompanyContextSchema = z.object({
  fabricTypes: z.array(z.string()).optional().default([]),
  month: z.number().min(1).max(12).optional().default(new Date().getMonth() + 1),
  revenueRange: z.enum(['under_5cr', '5cr_to_50cr', 'above_50cr']).optional().default('5cr_to_50cr'),
})

const RequestBodySchema = z.object({
  cccResult: CCCResultSchema,
  companyContext: CompanyContextSchema.optional().default({}),
  layer1Candidates: z.array(Layer1CandidateSchema),
})
```

### 3b — Fallback generator (used when Gemini fails)

```typescript
function buildFallbackRecommendations(candidates: Layer1Candidate[]): Recommendation[] {
  const priorityLabel = (p: number): 'HIGH' | 'MEDIUM' | 'LOW' =>
    p >= 8 ? 'HIGH' : p >= 5 ? 'MEDIUM' : 'LOW'

  return candidates.slice(0, 5).map(c => ({
    id: c.id,
    dimension: c.dimension,
    priority: priorityLabel(c.priority),
    title: c.title,
    explanation:
      `Your ${c.dimension} metric is outside the textile industry benchmark. ` +
      `Addressing this could reduce your Cash Conversion Cycle by approximately ${c.estimatedDaysReduction} days.`,
    actionSteps: [
      `Review your ${c.dimension} data for the past 30 days`,
      `Identify the top 3 counterparties contributing to this gap`,
      `Schedule a follow-up with your finance team this week`,
    ],
    estimatedDaysReduction: c.estimatedDaysReduction,
    estimatedCashFreedLakhs: Math.round(c.estimatedDaysReduction * 0.8 * 10) / 10,
  }))
}
```

### 3c — The route handler

```typescript
import { NextRequest, NextResponse } from 'next/server'
import { getGeminiModel, SYSTEM_PROMPT } from '@/lib/recommendations/geminiClient'

export async function POST(req: NextRequest) {
  // 1. Parse and validate body
  let body: unknown
  try {
    body = await req.json()
  } catch {
    return NextResponse.json({ error: 'Invalid JSON body' }, { status: 400 })
  }

  const parsed = RequestBodySchema.safeParse(body)
  if (!parsed.success) {
    return NextResponse.json(
      { error: 'Invalid request body', details: parsed.error.flatten() },
      { status: 400 }
    )
  }

  const { cccResult, companyContext, layer1Candidates } = parsed.data

  // 2. If no candidates from Layer 1, return empty
  if (layer1Candidates.length === 0) {
    return NextResponse.json({ recommendations: [] })
  }

  // 3. Build the user message for Gemini
  const userMessage = JSON.stringify({
    cccResult,
    companyContext,
    layer1Candidates,
  })

  // 4. Call Gemini — always wrapped in try/catch
  try {
    const model = getGeminiModel()

    const result = await model.generateContent([
      { text: SYSTEM_PROMPT },
      { text: userMessage },
    ])

    const responseText = result.response.text()

    // 5. Parse Gemini JSON response
    let parsed: { recommendations: Recommendation[] }
    try {
      parsed = JSON.parse(responseText)
    } catch {
      console.error('[recommendations] Gemini returned non-JSON:', responseText.slice(0, 200))
      // Fallback — don't expose the error to the user
      return NextResponse.json({
        recommendations: buildFallbackRecommendations(layer1Candidates),
        source: 'fallback',
      })
    }

    // 6. Validate Gemini returned the right shape
    if (!Array.isArray(parsed?.recommendations)) {
      return NextResponse.json({
        recommendations: buildFallbackRecommendations(layer1Candidates),
        source: 'fallback',
      })
    }

    return NextResponse.json({
      recommendations: parsed.recommendations.slice(0, 5), // hard cap at 5
      source: 'gemini',
    })

  } catch (error) {
    // Gemini API error (rate limit, invalid key, network, etc.)
    // Log server-side, return fallback to user — never a 500
    console.error('[recommendations] Gemini API error:', error)
    return NextResponse.json({
      recommendations: buildFallbackRecommendations(layer1Candidates),
      source: 'fallback',
    })
  }
}
```

## What to Check in the Response

| Check | Pass condition |
|-------|---------------|
| HTTP status | Always 200 — never 500 |
| `recommendations` array | 1–5 items, never more than 5 |
| Each item has `priority` | Exactly `"HIGH"`, `"MEDIUM"`, or `"LOW"` |
| Each item has `actionSteps` | Array of exactly 3 strings |
| `source` field | `"gemini"` when API works, `"fallback"` when it doesn't |
| Fallback still returns data | Yes — never an error object |

## Rules

- Never return HTTP 500 — all errors fall back to Layer 1 candidates
- Never expose `GEMINI_API_KEY` in client-side code or response bodies
- The `source` field in the response is for debugging only — the UI does not display it
- Hard cap: always `.slice(0, 5)` before returning, even if Gemini returns more
- TypeScript strict mode is on — no `any` except where explicitly noted above
