# Synthetic Test Datasets

Generated by `npx tsx test-data/generate.ts` (re-run any time to regenerate).
Each scenario is verified through the app's **real** parser and CCC engine at
generation time — the numbers below are what the app itself computes.

Upload the three files from a scenario folder into the widget at
`localhost:3000` (or drag `all-in-one.xlsx` onto any single slot).

## Scenarios

### `healthy-mill/` — the good-news path
DIO 25.6 · DSO 30 · DPO 49.5 · **CCC 6.1** (35 days *under* the 41-day benchmark)

What to check: metric cards all green, "Rs 0.0 lakhs locked", **no
recommendation cards** — instead the green "No urgent actions found" state.

### `stressed-mill/` — the worst-case path
DIO 61.6 · DSO 75 · DPO 28 · **CCC 108.6** (+68 days, ~Rs 1.8 Cr locked)

What to check: red metrics everywhere, "Rs 181.6 lakhs locked" derived from
the real ₹2.4 Cr revenue in the file, and **5 recommendation cards**
(R1/R2/R3/R5 HIGH + R4 MEDIUM). With a valid Gemini key you should see the
"✦ AI-personalised" badge and explanations quoting these exact numbers.

### `messy-tally-export/` — the hostile real-world file
Same upload flow, but the files contain everything a real Tally export throws
at a parser: company-name title rows above the header, blank rows mid-data,
amounts as `₹22,00,000` / `Rs. 16,25,000` / `18,50,000.00`, mixed
`DD-MMM-YYYY` and `DD/MM/YYYY` dates, Tally's `Particulars`/`Vch No.` column
names, and a `Grand Total` footer row.

What to check: it still parses (6 sales / 4 purchases / 3 stock rows), the
Grand Total row is skipped rather than counted as an invoice, and warnings
about the unrecognised party column don't block the analysis.
Result: CCC 129.8 (+89 days), 5 recommendations.

### `all-in-one.xlsx` — single-workbook convenience path
The healthy-mill data as one workbook with three sheets. Drop it on **any one
slot** — the app should detect all three registers and fill all slots at once.

### `broken/Salary_Sheet.xlsx` — the error path
An employee salary sheet with no invoice columns at all.

What to check: upload it (plus any two real files) and the widget should show
the friendly red error explaining the file couldn't be read — never a crash,
never NaN metrics.

## Bonus check: trends

Upload `healthy-mill` first, then `stressed-mill`. The second result should
show red ↑ trend badges on the metric cards ("vs last run"), and `/dashboard`
should list both analyses with deltas.
